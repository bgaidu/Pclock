## 0. TL;DR（一句话总览）

PCLock 是一个面向 Windows 7/10/11 的**家长控制程序**：后台倒计时、到点全屏锁屏、孩子需连续答对 10 题或用家长 PIN 解锁；通过**注册表持久化 + UTC 时间戳断电折算 + 双进程互守护 + 进程 DACL 自保护 + 低级键盘钩子**构成防作弊闭环；已具备零依赖单元测试 53 项与 CI，代码已分模块的 partial 结构。**尚未完成的是 16 项真机手动回归（B 部分）与 VS/MSBuild 通道实跑**。

### 1.4 已知问题 / 设计边界（非缺陷，多为有意取舍）

| 问题 | 性质 | 说明 / 处置 |
|---|---|---|
| **管理员账户可杀进程** | 预期行为 | DACL 仅拒标准用户；管理员持 `SeDebugPrivilege` 必能结束自身进程（否则家长会锁死自己）。孩子必须用标准用户账户。 |
| **任务管理器显示 2 个进程** | 预期行为 | 双进程互守护设计（1 主 + 1 看门狗），并非 bug。 |
| **30 秒断电阈值可被利用** | 设计取舍（P2-4） | 离线 <30s 视为正常关机延迟不扣时；需物理断电能力，记录为已知边界，阈值不建议动。 |
| **Ctrl+Alt+Del 无法屏蔽** | 系统限制 | Windows 安全序列；靠「标准用户 + 锁屏禁任务管理器 + 重新登录即恢复锁屏」兜底。 |
| **安全模式不触发计划任务** | 系统限制 | 安全模式计划任务不启动；标准用户仍无法删程序/注册表，正常开机后锁屏恢复。 |
| **TickCount 49.7 天回绕** | 理论边界（P2-2） | 锁屏冷却用 `Environment.TickCount`，回绕边界理论可致冷却跳变；兼容 .NET 4.0 无 `TickCount64`，建议用 `(long)(uint)TickCount` 差值。 |
| **`static Random rnd` 非线程安全** | 潜在风险（P2-1） | 当前仅 UI 线程使用，无害；后台预生成题目时需改每线程实例。 |
| **PIN 冷却可被改系统时间绕过** | 低收益（P2-3） | 需管理员权限且与 UTC 折算叠加后实际获利有限。 |
| **修改 Mutex 为 `Global\` 不可行** | 已否决方案 | 标准用户无 `SeCreateGlobalPrivilege`，`Global\` 会使孩子的单实例 Mutex 创建失败 → 多实例。保持 `Local\`。 |

## 3. 技术方案、架构设计与核心实现

### 3.1 技术栈

- **语言/框架**：C# + Windows Forms，.NET Framework 4.7.2（目标）/ 4.0（运行时兼容）。
- **构建**：双通道 —— 命令行 `build.bat`（系统 `csc`，零依赖）+ VS2022 `PCLock.csproj`（`src\**\*.cs` 通配 + `BeforeBuild` 调 `gen_version.bat`）。
- **测试**：自研零依赖框架 `tests/TUnit.cs`（`[Test]` + `Assert` + 反射 Runner），系统 `csc` 编译运行，53 项确定性单测；CI 由 GitHub Actions 自动执行。
- **无远程依赖**：纯本地 Win32 + 注册表 + 计划任务。

### 3.2 架构设计（当前态 + 目标态）

**当前形态**：单程序集、双进程。主进程负责全部业务逻辑，看门狗进程（`--watchdog`）守护主进程。已做的模块化：`App.cs` 按职责拆分为 partial（`App.cs` 核心 + `App.Tray`/`App.Guard`/`App.Power`/`App.Shutdown`），`StartupManager` 抽取为独立静态类；`PinDialog`/`AboutForm`/`LowLevelHook` 独立文件。

```
开机 → schtasks(ONLOGON/HIGHEST/DELAY30) ┐
        HKLM Run 键（回退）              ┴→ 主进程(PCLock.exe)
                                            ├─ 托盘 + 1s 倒计时 + 锁屏调度 + 注册表持久化
                                            ├─ 低级键盘钩子 + 全屏锁屏(UiTick 置顶抢焦点)
                                            └─ 看门狗(--watchdog)：Mutex 消失则重启主进程
                                         双进程经 Local\ Mutex/EventWaitHandle 互认存活
```

**目标分层架构**（已在架构文档规划，未全量落地，供新成员参考）：

```
L0 入口宿主    Program.Main（启动编排/异常/单实例）
L3 表现层      TrayController / LockForm / SettingsForm / PinDialog / AboutForm
L2 领域层(纯逻辑,可单测)  SessionTimer / TimeWindow / QuestionEngine / PinHasher
L1 系统集成层  RegistryStore / StartupManager / SelfProtection / WatchdogHost / PowerEventBridge
横切           Logging / Constants / AppVersion
```

> 关键约束：**核心层（Store）不依赖入口层（Program）**——已通过 `Store.SetLogSink` 注入实现（M3 修复）。`build.bat` / `tests/run.bat` 用通配/清单收集，新增 `.cs` 不需改 `build.bat`（但 `tests/run.bat` 需显式登记测试文件，因其刻意不编译 `Program.cs` 以免第二个 `Main`）。

### 3.3 核心方法与关键实现思路

1. **双进程互守护（防杀/防卸载残留）**
   - 主进程持 `Local\PCLock_Main` Mutex；构造时即 `EnsureWatchdog()` 拉起看门狗；`Shutdown` 先 `Set` `Local\PCLock_Stop` 事件通知看门狗退出，再 `WaitWatchdogExit`（轮询看门狗 Mutex 消失，上限 6s）后删目录。
   - 看门狗进程 `OpenExisting` 主 Mutex，消失则拉起主进程；互拉逻辑均先确认对方不存在，幂等无竞态。
   - 意义：单进程可被任务管理器结束；两进程互拉 + DACL 形成多重防护。

2. **剩余时间按"剩余秒数"递减（防改时间）**
   - 计时直接 `RemainingSeconds--`，与系统时间无关；改系统时间无法重置倒计时。

3. **UTC 时间戳断电折算（防直接断电）**
   - 每 15s 持久化 `RemainingSeconds` + `LastSeenUtc`（UTC 墙钟刻度）。下次启动 `Store.DeductOffline`：若离线 >30s 阈值，扣减离线时长（向上取整到秒，防整数除法少扣）；时间戳只减不增，时钟回拨不获利。
   - 正常关机/休眠（SessionEnding/PowerModeChanged）清 `LastSeenUtc=0`，不扣时长。

4. **PIN 抗离线枚举（PBKDF2）**
   - 新格式 `pbkdf2$<iter>$<salt>$<hash>`，25000 迭代 + 随机盐；旧 `SHA256` 格式验证成功自动升级；HKLM 普通用户可读，故 4 位 PIN 用裸哈希可被瞬间枚举——PBKDF2 把离线成本提高约两万余倍。验证在后台线程执行（约 0.2s，UI 不卡）。

5. **进程 DACL 自保护（手工构造安全描述符字节）**
   - `Protection.cs` 手工构造 SD/ACL/ACE 字节（拒绝 Everyone 的 TERMINATE/WRITE_DAC/SUSPEND_RESUME），退出/卸载时恢复空 DACL。**字节布局极脆弱，任何改动必须真机回归**——属「不建议改」区（见 4.5）。

6. **全屏锁屏 + 低级键盘钩子（防绕过）**
   - `LockForm` 覆盖整个 `VirtualScreen` 且 `TopMost`；`UiTick` 每 500ms 重设全屏/置顶/抢焦点（打开家长对话框时经 `SuspendInteraction` 暂停，避免把设置窗口压到底层）；低级键盘钩子 `WH_KEYBOARD_LL` 屏蔽 Win/Alt+Tab/Ctrl+Esc/Shift+Tab/Alt+方向键；`WM_SYSCOMMAND` 拦截关闭/最小化/最大化/任务栏/Alt 菜单；锁屏期间写 `DisableTaskMgr` 策略禁任务管理器。

7. **答题状态机（防碰运气）**
   - 一次 10 题互不重复（数学口算/语文选拼音+释义/英语选词四选一）；答错任意一题全部清零、等 5s 从第 1 题重来；家长 PIN 连续 5 败进入全局 30s 冷却。

8. **每日可用时段（支持跨午夜）**
   - `Store.IsWithinWindow`：`a<=now<=b`；当 `a>b` 按跨午夜环绕（`now>=a || now<=b`）。格式 `08:00-12:00;14:00-21:00`，分号/逗号分隔，留空=全天，非法段忽略；时段外硬锁（不计时、仅 PIN 解锁）。

9. **高 DPI 兼容**
   - Win8.1+ `SetProcessDpiAwareness(PerMonitor)`；Win7 回退 `SetProcessDPIAware`；自动检测 API 存在性。

### 4.3 运行与部署步骤

**安装（只需一次）**
1. 在固定目录（建议 `C:\Program Files\PCLock\`）放入 `PCLock.exe` 与 `PCLock.exe.config`（**必须同目录，路径建议固定，勿随意挪动**）。

### 4.5 交接注意事项（避坑清单，强烈建议阅读）

1. **「不建议改」的高风险区**（改前必读架构文档 2.4）：
   - `Protection.cs` DACL 字节布局（手工构造 SD/ACL/ACE，字节级脆弱，曾出结构错误事故）；
   - 键盘钩子按键组合与拦截顺序；
   - PBKDF2 迭代次数（25000）；
   - 防作弊参数（UTC 折算、30s 阈值、答错清零、15s 持久化频率）；
   - 锁屏 500ms 置顶抢焦点策略。
   任何改动必须真机完整回归。

2. **Mutex 用 `Local\` 不用 `Global\`**：因计划任务 `/SC ONLOGON` 与手动同登录会话，`Local\` 已互通；`Global\` 需 `SeCreateGlobalPrivilege`，标准用户无此权限会导致孩子端单实例失效 → 多实例。

3. **每次改动构建脚本、拆分文件、增删 `using`，必须真机跑 `tests\run.bat` + `build.bat`**：静态复查抓不到标识符级错误与批处理语义错误（M4 实测暴露 5 个，其中 1 个是 CI 假绿级）。

4. **构建失败时 `bin\` 旧 exe 不自动删**：务必核对输出文件时间戳确认是当次产物（曾差点误判）。

5. **`tests/run.bat` 用显式清单、不编译 `Program.cs`**：新增测试 `.cs` 须在 `run.bat` 登记，并在 `tests/UnitTests.cs` 的 `Program.Main` 注册测试类，运行器才会发现。

6. **新增 `src/*.cs` 不需改 `build.bat`**（已通配）；但 `tests` 测试文件需手动登记。

7. **C# 语法保持 4/5 兼容**：勿用字符串插值/`nameof`/新特性，以兼容系统 `csc` 与 .NET 4.0 运行时。新增可单测核心逻辑须登记进 `tests\run.bat` 清单与 `UnitTests.cs`。

8. **标准用户账户验证未做**：DACL 防杀、防删注册表/文件的防护只在「孩子=标准用户」场景下成立；管理员账户已知可绕过（见 1.4）。

9. **`bin/`、`obj/`、`err.txt`、`_Version.cs`、`.workbuddy/` 均已 gitignore**，不会入库；`PCLock.exe` 也不入库（由构建生成）。
